# NEXT SESSION — 改変項目インデックス設計の議論用シード

## 目的

シナリオ改変が航空、艦艇、暗号、基地、兵站、人事、戦術学習、技術時計などへ広がり、圧縮サマリーのみでは中核条件が脱落し得ることが判明した。

次回はシナリオ継続より先に、**実行時にどの改変を必ず読み込ませるかを機械的に保証する索引**を設計する。

この文書は最終仕様ではなく、議論開始用。

---

## 議論したい設計案

### A. 常時コア・インデックス

全戦闘・全時期で必ず読み込む少数の不変条件。

候補：

- 計算機性能・世代時計
- 暗号防御／解読能力
- 技術採用時計と「存在≠配備」規則
- 機体／搭乗員分離
- 即応率・整備・基地運用
- 艦艇 availability / damage-control / sensor / AA の基本差
- 兵站・船腹・捕獲資産規則
- 組織改革・学習の発火条件
- UNKNOWN / probabilistic difference 規則

### B. 時期×戦域インデックス

例：`1942-05 / SOUTH_PACIFIC / CARRIER_AIR / SIGINT / SEAPLANE_BASE`

該当期間・戦域に入った時だけ、関係する正本を追加ロードする。

### C. Switch Registry の拡張

各改変を switch / state variable として機械可読化する。

候補フィールド：

- `id`
- `domain`
- `effective_from`
- `maturity_state`
- `theater_scope`
- `platform_scope`
- `affected_variables`
- `mechanism`
- `constraints`
- `opportunity_cost`
- `dependencies`
- `source_files`
- `historical_baseline`
- `current_injection_status`
- `last_audited_date`
- `do_not_generalize_to`

### D. 「戦闘前チェックリスト」の自動生成

各イベント開始時にインデックスから、

- この戦闘に効く機体差
- 艦艇差
- 基地差
- 暗号／偵察差
- 人員差
- 兵站差
- 敵側適応

を列挙し、未検討項目があれば戦闘計算を止める。

---

## 特に再発防止したいこと

- `70_暗号...` のような中核正本がサマリーから消え、史実値へ吸着する。
- 航空改善を陸軍／海軍、機種、部隊、時期をまたいで無断転用する。
- 基地建設改善と機体性能改善を混同する。
- 艦艇の改変が存在するのに、史実艦性能のまま戦闘を流す。
- 保存された機体・搭乗員を、所属不明のまま都合の良い戦隊へ配賦する。
- 「情報を得た」ことを「司令部が信じた」「現場が実行した」と同一視する。
- 後年に発火する改革を1942年へ先取りする。
