# ENGINE REQUIREMENT / TEAM RELEASE CANON — V8 AIRPOWER2

> **AIRPOWER2 current engine-line chronology authority.** This file supersedes blanket “historical start month + efficiency scalar” and “earlier engine team release -> every later engine moves left by the same number of months” reasoning. Historical requirement clocks still matter. Earlier development may deepen concept work, rigs, supplier prep and test-method maturity; it does not automatically create an earlier formal military specification.

## 0. Core decision

For every engine line, separate at least five clocks:

1. **requirement clock** — formal service/customer requirement or manufacturer product objective;
2. **concept clock** — internal architecture / pre-design work;
3. **team-release clock** — when a qualified design/test group is actually free enough to move to the next job;
4. **physical clock** — tooling, materials, rigs, endurance, supplier learning and production process;
5. **service clock** — qualification, production acceptance, aircraft integration and unit conversion.

A later line may advance only where the relevant clock has a paid causal bridge.

## 1. What efficient earlier work can legitimately move

If an earlier project converges faster and releases people earlier, the next line may receive earlier:

- architecture trade studies;
- compressor/supercharger/combustion concept work;
- material-coupon and bearing rigs;
- torsion/rotordynamics calculations;
- supplier discussions and long-lead tools;
- prototype component work;
- serviceability/maintenance planning;
- failure-mode test design.

What cannot be moved without a separate event:

- a formal Army/Navy specification that has not yet been issued;
- customer procurement budget;
- airframe integration requirement that does not exist;
- production authorization;
- training/unit deployment;
- material availability that depends on another program.

## 2. Internal product work before formal service requirement

Asai and other companies may develop a private/company product or technology demonstrator before the military requirement. This is not a workaround for the gate; it changes what exists when the gate opens.

Thus the correct sequence can be:

`company concept -> component rigs -> demonstrator -> formal military requirement -> rapid adaptation/qualification`

instead of:

`formal military requirement -> concept begins from zero`.

This is especially important for turbine, exhaust-thrust, turbo, controls, materials and calculation infrastructure.

## 3. Engine-family continuity

A new engine requirement does not imply abandoning the older engine. Lower-generation engines may continue because they are cheaper, longer-lived or already tooled. Later technology may also flow backward as process/QC improvement without changing the old engine's designation.

Use:

- new architecture/major rating family only when the design really changes;
- service-equivalent/process-improved older product when interfaces remain compatible;
- separate prototype/production/service labels.

## 4. Customer team-release rule

When an external manufacturer (Nakajima, Mitsubishi, Kawasaki, etc.) receives Asai support, the external design team does not become Asai. It receives the transferred method/equipment/training actually supplied. Its future release date depends on:

- how much of the design/test burden was removed;
- whether the same team is simultaneously maintaining existing production;
- military redesign demands;
- supplier and tooling problems;
- unexpected local failures.

No universal “Asai support = team released X months early” scalar is allowed.

## 5. AIRPOWER2 use

For the current 1939–41 audit, every historical piston engine/program must be checked against:

- current Asai-origin calculation/test/QC methods already diffused by that date;
- exhaust/cooling/propeller state;
- materials and surface-treatment state;
- actual manufacturer team workload;
- formal Army/Navy requirement date;
- aircraft project interface.

If a program is advanced, state which clocks moved and which did not.

## 6. No-backflow

A later successful engine, aircraft, or combat result is not evidence that its earlier requirement was known or funded. Future outcome may motivate an audit question but not supply actor knowledge.
